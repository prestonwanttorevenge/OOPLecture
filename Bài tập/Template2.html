1. Lập trình tổng quát (Generic Programming)

Khái niệm cơ bản

Ngài cứ hiểu đơn giản, lập trình tổng quát là cách viết code mà không cần quan tâm trước dữ liệu là kiểu int, float hay string [cite: 139]. Tư tưởng ở đây là ta xây dựng sẵn một "công thức logic" chung nhất, lúc nào xài thì mới nhét kiểu dữ liệu cụ thể vào [cite: 139].

Lấy ví dụ hàm hoán đổi (Swap) hai biến số nguyên [cite: 141]:

void swap(int a, int b) {
    int temp = a; a = b; b = temp;
}

Nếu ngài muốn hoán đổi hai số thập phân float, ngài lại phải hì hục gõ lại y chang đoạn code trên, chỉ đổi mỗi chữ int thành float [cite: 141]. Điều này cực kỳ mất thời gian và dư thừa code [cite: 141].

Ví dụ cấu trúc Ngăn xếp (Stack)

Nếu ta tạo một cái giỏ (Stack) chuyên để đựng số nguyên int [cite: 142]. Nhỡ hôm sau ta cần cái giỏ đựng chữ char thì sao? Lẽ nào lại phải copy code ra tạo thêm cái CharStack, FloatStack? [cite: 142]. Cách viết cứng ngắc kiểu dữ liệu thế này rất bất lợi [cite: 143]. Đó là lý do ta cần lập trình tổng quát [cite: 143].

2. Cách người xưa làm trong ngôn ngữ C

Thời chưa có C++, các cụ lập trình viên dùng mẹo Trình tiền xử lý (Preprocessor) để thay thế chữ [cite: 144]. Dùng #define để dán nhãn kiểu dữ liệu [cite: 144]:

#define TYPE int

void swap (TYPE & a, TYPE & b) {
    TYPE temp = a; a = b; b = temp;
}

Trước khi dịch code ra mã máy, máy tính sẽ đi dò tìm toàn bộ chữ "TYPE" và copy-paste chữ "int" đè lên đó [cite: 144].

Nhược điểm chí mạng:

  • Máy tính nó chỉ thay thế văn bản một cách mù quáng chứ không kiểm tra xem logic code có đúng không. Cực kỳ dễ sinh lỗi [cite: 144].
  • Chỉ xài được 1 kiểu duy nhất cho cả chương trình [cite: 144]. Khi ngài đã #define TYPE int, thì cả bài code đó cái hàm swap chỉ xài được cho số nguyên. Muốn xài cho float cũng chịu chết.

3. Đẳng cấp của C++ Template

Để sửa sai cho C, C++ mang đến Khuôn mẫu (Template). Nó là cơ chế cho phép ta viết code mà không cần chốt cứng kiểu dữ liệu ngay từ đầu [cite: 145].

Ngài dùng từ khóa template để báo cho máy biết: "Này, đoạn code bên dưới ta sẽ dùng một kiểu dữ liệu ẩn danh, lát nữa ta truyền vào sau nhé" [cite: 145]. Cái kiểu ẩn danh đó được đặt trong ngoặc nhọn < > [cite: 145].

template <typename T>
// Dưới này ngài cứ lấy chữ "T" ra xài như một kiểu dữ liệu bình thường.

Chú ý: Ngài viết template ở đâu thì nó chỉ linh nghiệm cho duy nhất 1 cái hàm hoặc 1 cái class nằm ngay sát bên dưới nó thôi nhé [cite: 145].

Có hai loại khuôn mẫu chính là Khuôn mẫu cho Hàm và Khuôn mẫu cho Lớp (Class/Struct) [cite: 146].

4. Khuôn mẫu hàm (Function Template)

Giờ ta viết lại hàm Swap xài template [cite: 147]:

template <typename T>
void swap(T & a, T & b) {
    T temp = a; a = b; b = temp;
}

Lúc xài, ngài cứ quăng số nguyên hay số thực vào, C++ sẽ tự hiểu [cite: 148]:

int x = 1, y = 2;
float a = 1.1, b = 2.2;

swap(x, y); // C++ tự suy ra T là int
swap(a, b); // C++ tự suy ra T là float

Máy tính xử lý vụ này như thế nào? (Under the Hood)

Bệ hạ lưu ý kỹ điểm này: Sự thay thế chữ "T" ở đây KHÔNG giống trò copy-paste văn bản mù quáng của ngôn ngữ C [cite: 148]. Quá trình này được làm bởi Trình biên dịch (Thợ xây code) [cite: 148].

  1. Khi ngài gọi swap(x, y) với x, y là số nguyên. Thợ xây code sẽ chạy đi tìm xem ngài có lén viết cái hàm swap bình thường nào cho số nguyên không [cite: 149].
  2. Nếu không có, nó thấy cái Bản thiết kế Template. Nó lấy ra xem thử [cite: 149].
  3. Nó đối chiếu: "À, ngài truyền vào 2 cái int. Trong bản vẽ yêu cầu 2 biến cùng kiểu T. Vậy khớp lệnh, T chắc chắn là int!" [cite: 149].
  4. Sau đó, Thợ xây tự động viết giùm ngài một cái hàm swap hoàn chỉnh dành riêng cho int và nhét ngầm vào trong file chạy [cite: 150]. Quá trình này gọi là Khởi tạo khuôn mẫu.

Vậy lợi và hại là gì?

  • Hại (Tốn dung lượng): Nếu ngài gọi hàm này cho 10 kiểu dữ liệu khác nhau, Thợ xây sẽ âm thầm đẻ ra 10 cái hàm khác nhau giấu trong máy [cite: 151]. Tốn thời gian dịch code và làm phình to file chạy [cite: 151].
  • Lợi (Tốc độ bàn thờ): Bù lại, vì nó tạo sẵn từng hàm riêng lẻ cho từng kiểu, nên lúc chạy chương trình, máy tính không cần phải tính toán suy luận gì nữa, tốc độ chạy nhanh y như ngài tự gõ code tay [cite: 151].

5. Khuôn mẫu lớp (Class Template)

Cách làm cũng y chang hàm, nhưng dùng để tạo Class/Struct [cite: 152]. Ví dụ cấu trúc Pair (Cặp dữ liệu) nhận 2 kiểu khác nhau [cite: 153]:

template <typename T, typename U>
struct Pair {
    T first;
    U second;
};

Chỗ này rất dễ dính bẫy (Lỗi bộ nhớ)

Với hàm, C++ tự đoán được kiểu. Nhưng với Class, bệ hạ bắt buộc phải khai báo rõ ràng kiểu dữ liệu trong cặp ngoặc nhọn < > [cite: 154].

Pair p;              // BÁO LỖI NGAY TỨC KHẮC!
Pair<int, float> r;  // Khai báo đúng.

Tại sao Class lại khắt khe như vậy? [cite: 154]

Khi ngài khai báo một Class (như tạo một cái thùng chứa), máy tính phải cấp phát bộ nhớ RAM ngay lập tức [cite: 154]. Nếu ngài không nói rõ đựng cái gì, máy tính không biết nên cấp cái thùng 4 bytes (đựng int) hay 8 bytes (đựng double) [cite: 154]. Khai báo <int, float> chính là chỉ thị kích thước cho cái thùng RAM đó.

Cách viết code an toàn cho Class

Kinh nghiệm xương máu: Ngài hãy tạo một Class bình thường trước (ví dụ cho int), chạy thử ngon lành hết lỗi đi đã, rồi mới gắn chữ template vào để tổng quát hóa [cite: 157].

Thêm lệnh template lên đầu class [cite: 160]:

template <typename T>
class Stack {
public:
    void push(const T& i);
private:
    T contents[10];
    int current;
};

Đặc biệt: Khi ngài đem mấy cái hàm ra ngoài Class để viết (dùng dấu ::), ngài phải kèm theo cái đuôi <T> cho tên Class, và phía trên mỗi hàm đều phải có chữ template [cite: 161].

template <typename T>
void Stack<T>::push(const T& i) {
    // Viết code trong này...
}

6. Tham số phi kiểu (Non-type Parameters)

Dấu < > không chỉ dùng để nhét "Kiểu dữ liệu". Ngài có thể nhét thẳng một Con số thực sự vào đó (thường là số nguyên) [cite: 164].

Ví dụ cái giỏ Stack ở trên kích thước cứng là 10 [cite: 165]. Nhỡ ta muốn mỗi cái giỏ có kích thước khác nhau thì sao? [cite: 165]

template <typename T, int I> // I chính là con số quy định kích thước
class Stack {
private:
    static const int max = I; 
    T contents[max];
};

Cách sử dụng cực kỳ mượt mà [cite: 168]:

Stack<int, 5> s;   // Tạo giỏ đựng 5 số nguyên
Stack<int, 10> t;  // Tạo giỏ đựng 10 số nguyên

Ràng Buộc Của Con Số Này:

  • Chỉ nhận số nguyên (int, char) hoặc con trỏ, tham chiếu [cite: 169]. Cấm bỏ số thực (float, double) vào.
  • Vì máy tính phải tạo ra cái giỏ RAM ngay từ lúc dịch code, nên con số này phải biết trước, không được thay đổi (Hằng số). Ngài không thể làm trò gán I = 20 ở giữa chừng được đâu nhé [cite: 169].

7. Kỹ thuật Lồng Template (Nâng cao)

Đây là chiêu thức cao cấp: Một tham số của Template lại chính là một Template khác chưa xác định [cite: 170].

Giả sử ta làm cuốn từ điển (Map) ánh xạ Từ khóa (Key) tới Giá trị (Value). Ta muốn người dùng tự do chọn cái túi đựng (Container) cho mớ dữ liệu này (có thể chọn túi Stack, hoặc túi Queue) [cite: 170].

template <typename K, typename V, template <typename T> class Container>
class Map {
private:
    Container<K> keys;    // Cái túi đựng Khóa (Key)
    Container<V> values;  // Cái túi đựng Giá trị (Value)
};

Lúc dùng, ngài quăng cái túi Stack vào [cite: 171]:

Map<string, int, Stack> wordcount;

Khi máy tính đọc dòng này, nó sẽ lấy ngay bản thiết kế Stack của ngài, tự động rập khuôn đẻ ra 2 cái túi là Stack<string> và Stack<int> để xài cho cuốn từ điển [cite: 172]. Quá vi diệu!
