1. Đa hình là gì?

Thuật ngữ Polymorphism có nguồn gốc từ tiếng Hy Lạp, trong đó "poly" nghĩa là nhiều, và "morphs" nghĩa là hình thái. Do đó, Đa hình (Polymorphism) có nghĩa là "có nhiều hình thái khác nhau".

Trong lập trình, Đa hình là khả năng một thông điệp (message) hoặc một tên gọi (name) có thể đại diện cho nhiều loại đối tượng khác nhau hoặc hành vi khác nhau, tùy thuộc vào ngữ cảnh mà nó được sử dụng.

Ví dụ thực tế

Hãy tưởng tượng hành động "Phát tiếng kêu". Nếu bạn yêu cầu một con Chó phát tiếng kêu, nó sẽ sủa "Gâu Gâu". Nếu bạn yêu cầu một con Mèo, nó sẽ kêu "Meo Meo". Hành động là MỘT (Phát tiếng kêu), nhưng HÌNH THÁI thực thi lại ĐA DẠNG tùy thuộc vào đối tượng tiếp nhận lệnh.

2. Đa hình hàm (Function Polymorphism)

Đa hình hàm xảy ra khi chúng ta có nhiều hàm cùng tên, nhưng khác nhau về chữ ký tham số (số lượng tham số, kiểu dữ liệu tham số). Trình biên dịch sẽ tự động xác định hàm nào được gọi dựa trên ngữ cảnh truyền tham số.

Biểu hiện rõ nhất của đa hình hàm trong C++ là Function Overloading (Nạp chồng hàm) và Function Templates (Khuôn mẫu hàm).

// Ví dụ Nạp chồng hàm (Function Overloading)
class MathUtils {
public:
    // Hình thái 1: Tính tổng 2 số nguyên
    int add(int a, int b) { return a + b; }
    
    // Hình thái 2: Tính tổng 3 số nguyên
    int add(int a, int b, int c) { return a + b + c; }
    
    // Hình thái 3: Tính tổng 2 số thực
    double add(double a, double b) { return a + b; }
};

int main() {
    MathUtils math;
    math.add(5, 10);       // Gọi hình thái 1
    math.add(5.5, 2.3);    // Gọi hình thái 3
}

3. Đa hình và Hướng đối tượng

Trong triết lý Hướng đối tượng (OOP), Đa hình thường gắn liền với Kế thừa (Inheritance). Nó cho phép ta xử lý các đối tượng thuộc các Lớp dẫn xuất (Derived Classes) khác nhau thông qua một giao diện chung của Lớp cơ sở (Base Class).

Tại sao cần đa hình trong OOP?

  • Mở rộng linh hoạt (Extensibility): Cốt lõi của OOP là nguyên lý Open/Closed (Mở để mở rộng, Đóng để sửa đổi). Bạn có thể thêm các lớp con mới vào hệ thống mà không cần sửa đổi các hàm đang sử dụng lớp cha.
  • Tái sử dụng giao diện: Ta có thể tạo một mảng duy nhất chứa con trỏ của Lớp Cha, và duyệt qua mảng này để gọi một hàm duy nhất. Từng Lớp Con sẽ tự biết cách thực thi đúng logic của mình.

4. Đa hình tĩnh (Static Polymorphism) là gì?

Đa hình trong C++ được chia làm hai loại dựa trên thời điểm mà Trình biên dịch đưa ra quyết định liên kết hàm.

1. Đa hình Tĩnh (Compile-time)

Mọi quyết định về việc gọi hàm nào được đưa ra ngay lúc Biên dịch chương trình (Compile time). Còn gọi là Early Binding (Liên kết sớm).

Hiện thực thông qua:

  • Nạp chồng hàm (Function Overloading)
  • Nạp chồng toán tử (Operator Overloading)
  • Templates (C++ Templates)

Ưu điểm: Chạy siêu nhanh vì mọi thứ đã được chốt từ trước.

2. Đa hình Động (Runtime)

Quyết định gọi hàm của đối tượng nào chỉ được đưa ra vào Lúc chương trình đang chạy (Runtime). Còn gọi là Late Binding (Liên kết trễ).

Hiện thực thông qua:

  • Kế thừa (Inheritance)
  • Ghi đè phương thức (Method Overriding)
  • Hàm ảo (Virtual Functions)

Ưu điểm: Tính linh hoạt cực cao, cốt lõi của OOP.

5. Liên kết động (Dynamic Binding)

Liên kết (Binding) là quá trình gán một lời gọi hàm tới một khối mã thực thi của hàm đó.

  • Liên kết tĩnh (Static Binding): Xảy ra khi dùng lời gọi trực tiếp (như obj.show()). Compiler biết obj thuộc lớp nào, nó gắn chặt lệnh gọi với hàm của lớp đó.
  • Liên kết động (Dynamic Binding): C++ sử dụng Con trỏ (Pointer) hoặc Tham chiếu (Reference) của Lớp Cha để chứa đối tượng Lớp Con (Upcast). Trình biên dịch lúc này nhắm mắt phó thác việc tra cứu hàm cho quá trình Runtime.

Under The Hood: VTABLE và VPTR

Để hiện thực Liên kết động, C++ âm thầm tạo ra 2 cấu trúc dưới gầm máy:

  1. VTABLE (Virtual Table): Một mảng tĩnh chứa con trỏ hàm (function pointers). Mỗi Lớp có tối thiểu 1 hàm ảo sẽ sở hữu 1 VTABLE riêng. VTABLE ghi chú rõ hàm ảo nào trỏ về khối code nào.
  2. VPTR (Virtual Pointer): Một con trỏ ẩn được tự động nhúng vào mỗi ĐỐI TƯỢNG (object) khi nó sinh ra. VPTR này trỏ thẳng đến VTABLE của lớp mà đối tượng đó thực sự thuộc về.

Khi gọi basePtr->virtualFunc(), C++ tra cứu VPTR -> Mở VTABLE -> Tìm địa chỉ hàm chính xác -> Nhảy tới thực thi. Đó là Liên kết động!

6. So sánh Overloading và Method Overriding

Method Overriding (Ghi đè phương thức) là gì?

Overriding xảy ra khi Lớp con cung cấp một định nghĩa MỚI hoàn toàn cho một hàm đã được khai báo ở Lớp cha. Để Ghi đè hợp lệ, Hàm con phải có chữ ký hàm (tên, tham số, kiểu trả về) GIỐNG HỆT hàm cha.

Bảng Phân Biệt Chi Tiết:

Tiêu chí Nạp chồng (Overloading) Ghi đè (Overriding)
Định nghĩa Nhiều hàm cùng tên nhưng khác tham số. Hàm ở lớp con cùng tên, cùng tham số với hàm lớp cha.
Phạm vi (Scope) Thường xảy ra trong cùng một Class. Xảy ra giữa 2 Class có quan hệ Kế thừa (Cha - Con).
Chữ ký hàm BẮT BUỘC phải khác nhau. BẮT BUỘC phải giống hệt nhau.
Kiểu liên kết Liên kết tĩnh (Compile-time). Liên kết động (Runtime) - nếu dùng virtual.
Từ khóa virtual Không cần. Bắt buộc lớp cha phải có từ khóa virtual.

7. Hàm ảo (Virtual Function)

Hàm ảo là trái tim của Đa hình Động. Để kích hoạt liên kết trễ (Dynamic Binding), bạn phải khai báo hàm trong Lớp cơ sở bằng từ khóa virtual.

#include <iostream>
using namespace std;

class Animal {
public:
    // HÀM ẢO: Cho phép lớp con Ghi đè và C++ sẽ dùng VTABLE để gọi
    virtual void makeSound() {
        cout << "Some generic sound..." << endl;
    }
};

class Dog : public Animal {
public:
    // C++11 override: Cưỡng ép compiler kiểm tra xem có đúng là đang ghi đè không
    void makeSound() override {
        cout << "Gau Gau!" << endl;
    }
};

class Cat : public Animal {
public:
    void makeSound() override {
        cout << "Meo Meo!" << endl;
    }
};

void playSound(Animal* animal) {
    // ĐA HÌNH ĐỘNG Ở ĐÂY:
    // animal đang trỏ tới Dog hay Cat? Compiler KHÔNG BIẾT lúc biên dịch.
    // Lúc Runtime, VPTR của object sẽ mách bảo phải gọi hàm nào.
    animal->makeSound();
}

int main() {
    Dog d;
    Cat c;
    playSound(&d); // Output: Gau Gau!
    playSound(&c); // Output: Meo Meo!
}

8. Destructor ảo (Virtual Destructor)

Trong C++, nếu một lớp được thiết kế để làm Lớp cơ sở (Base class), bắt buộc phải khai báo Destructor của nó là hàm ảo (virtual ~Base()).

Nguy cơ Rò rỉ bộ nhớ (Memory Leak)

Khi bạn thực hiện thao tác xóa vùng nhớ qua con trỏ lớp cha: delete basePtr;. Nếu Destructor KHÔNG ảo, C++ sẽ dùng Liên kết tĩnh. Nó thấy basePtr có kiểu là Lớp Cha, nó CHỈ gọi Hàm hủy của Lớp Cha.

Hậu quả: Đối tượng Lớp Con bị chém bay phần lõi cha, phần mở rộng của Lớp Con (các biến new trong con) bị mắc kẹt lại trong RAM vĩnh viễn.

class Base {
public:
    Base() { cout << "Base constructor\n"; }
    
    // Nếu quên chữ virtual ở đây, ~Derived() sẽ KHÔNG BAO GIỜ được gọi
    virtual ~Base() { cout << "Base destructor\n"; } 
};

class Derived : public Base {
    int* array;
public:
    Derived() { 
        array = new int[100]; 
        cout << "Derived constructor\n"; 
    }
    ~Derived() { 
        delete[] array; // Dọn dẹp tài nguyên
        cout << "Derived destructor\n"; 
    }
};

int main() {
    Base* ptr = new Derived();
    delete ptr; // An toàn nhờ Virtual Destructor!
}

9. Lớp Trừu Tượng (Abstract Class) & Pure Virtual Function

Đôi khi, Lớp Cha quá chung chung đến mức việc khởi tạo một đối tượng từ nó là vô nghĩa (Ví dụ: Class Shape, bạn không thể vẽ một "Hình" chung chung, phải là Hình Tròn hoặc Vuông).

C++ hỗ trợ định nghĩa Lớp Trừu Tượng thông qua khái niệm Hàm ảo thuần túy (Pure Virtual Function).

Hàm ảo thuần túy (Pure Virtual Function)

Khai báo bằng cách thêm = 0 ở cuối khai báo hàm. Hàm này chỉ có khai báo giao diện, không có thân hàm. Ép buộc các Lớp Con bắt buộc phải Ghi đè.

class Shape {
public:
    // Pure Virtual Function -> Shape trở thành Abstract Class
    virtual void draw() = 0; 
    virtual double getArea() = 0;
    
    virtual ~Shape() {} // Luôn nhớ Virtual Destructor
};

class Circle : public Shape {
    double radius;
public:
    Circle(double r) : radius(r) {}
    
    // BẮT BUỘC phải cài đặt draw() và getArea()
    void draw() override { cout << "Drawing Circle\n"; }
    double getArea() override { return 3.14 * radius * radius; }
};

int main() {
    // Shape s; // LỖI BIÊN DỊCH! Không thể khởi tạo đối tượng từ Lớp Trừu Tượng
    Shape* s = new Circle(5.0); // HỢP LỆ: Con trỏ lớp trừu tượng trỏ tới con
    s->draw();
    delete s;
}

Quy tắc Lớp Trừu Tượng

  • Chỉ cần class chứa ÍT NHẤT MỘT Pure Virtual Function, class đó trở thành Abstract Class.
  • Không thể tạo Object (Instance) trực tiếp từ Abstract Class.
  • Nếu Lớp con kế thừa từ Lớp trừu tượng mà QUÊN KHÔNG định nghĩa (ghi đè) hàm thuần ảo, Lớp con đó cũng TỰ ĐỘNG trở thành Lớp trừu tượng.
  • Mục đích chính của Lớp trừu tượng là tạo ra Interfaces (Giao diện chuẩn) cho kiến trúc phần mềm.
